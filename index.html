Case 01 · Grove · personal finance hub

Bank statements in.
A retirement date out.

A privacy-first personal finance hub. Drop in a few months of statements and it works out what you actually spend, then projects the date you could stop working. The raw statements are never stored.

  • Role — sole author
  • May → Aug 2026
  • React · FastAPI · Supabase · Gemini
01

The problem

Every retirement calculator asks what you spend a month. Nobody knows what they spend a month.

The honest answer is buried in a year of statements spread across four institutions, in four different CSV and PDF layouts, none of which agree on what a column is. So people estimate, put the estimate in a spreadsheet, and get a retirement date accurate to about the nearest decade. The number that matters most is the one nobody checks.

02

The flow

Four steps, and the model only owns the one that genuinely needs judgment.

STATEMENTS ──▶ PARSE ──────▶ EXTRACT ─────▶ REVIEW ────▶ PROJECT

csv · pdf      pdfplumber     Gemini 3.1     you edit     hand-built
txt · image    + vision       Flash Lite     the table    SVG charts

Parsing is deterministic wherever it can be — dedicated readers for TD, CIBC, RBC and Scotiabank — and a model runs only where a layout defeats them. What the model returns is a proposal, not a verdict: the category table is editable, it runs entirely client-side, and nothing counts until you confirm it.

That boundary is also the privacy story. Raw files and transaction text are never stored, the review step never leaves the browser, and what persists is a summary behind Supabase Auth with Vault encryption.

03

Charts worth hand-building

A projection is one line, one target, and the point where they cross. That is not a charting-library problem.

The growth and trend charts are hand-written SVG. Owning the geometry is less code than bending a library into the shape of a crossing point, and it means the one moment that matters — the year the line meets the number — can be drawn deliberately instead of configured around.

04

Why every change ships with tests

AI wrote a lot of this. That is precisely the argument for a strict test policy, not against one.

When generated code arrives faster than anyone can read it line by line, review quietly stops being the quality gate. Something else has to be. So every change ships with tests: 25 of them across the frontend lib, the FastAPI service, the statement parsers, and a Playwright journey that drives the whole upload-to-projection path — all gated in CI.

It is the same instinct as the substrate in case 02. Decide the rule once, write it down, then make something other than my own attention responsible for holding it.

Case 02 · design-guide · sole author

Taste, elicited.
Design, enforced in CI

A personal design substrate: four tiers of knowledge, an app that infers taste from A/B picks rather than asking for adjectives, and a CLI that gates a built page against all of it. What comes out is a portable stance an agent can load before it builds.

  • Role — sole author
  • 2025 →
  • Node · CLI · static analysis
01

The problem

AI produces an enormous volume of competent, tasteless design. Design systems ship components; they do not ship judgment.

Competent, because the model absorbed the conventions. Tasteless, because it averages them — the output is the median of everything: correct spacing, safe type, the layout everyone else shipped. Nothing in it was chosen. And it cannot be fixed by asking, because elegant, minimal, with personality returns the median of those words too.

The same drift happens with no model in the room. The decisions that matter — how much space a block has earned, which rule is not tradeable against aesthetics — live in review comments and in whoever happened to be there. Nothing checks them. A month later the same argument runs again from zero.

02

Four tiers

Knowledge separated by how negotiable it is. The tier decides what the gate does when a page contradicts it.

  • 34

    Tier 1 · invariants

    Contrast, target size, visible focus, keyboard reach, labels. Never traded. A fail is a fail.

  • 21

    Tier 2 · preferences

    Stanced per project, each carrying the trade-off in writing. Unstanced means: ask, do not pick.

  • ↳

    Tier 3 · recipe index

    Named solutions retrievable by problem, not by component name. What to reach for, and when not to.

  • ◧

    Tier 4 · art direction

    Per project. Tokens derived from real visual references — never authored by hand, never a raw hex.

03

Elicitation, not a questionnaire

Nobody can describe their own taste in adjectives. Ask for adjectives and you get clean, modern, bold — three words that constrain nothing.

So the app never asks. It shows two candidates and takes a pick plus a reason. Six picks across five categories were enough to surface one meta-preference — space must be earned — because the reason given was never novelty or convention. It was always how the option used space or length.

A preference you can state is a preference you can trade. A preference inferred from six picks is one you can enforce.

04

The gate

One command. It reads the built page, not the source of truth someone promised to update.

node engine/cli.js gate index.html --project .
  ✓ invariants   34/34
  ✓ tokens       no raw hex, no magic px
  ⚑ preferences  1 flag — reason required

Fails are not negotiable. Flags require a stated reason, recorded next to the flag rather than in a chat log. Run it in CI and the argument stops being a matter of who reviews the pull request.

Case 03 · creative-library · 2018 → ongoing

37 recipes, each one verified

A technique corpus for the web. Every recipe renders in the browser, and every recipe has a harness that says whether it still does. Alongside it, a second shelf holds something different in kind: the identity system this page is wearing.

01

Eight years, one lineage

This is not two projects. It is a sketchbook and what happened when the sketches got a test.

  • 2018 → ongoing

    Interestingly Entertaining Interfaces

    The sketchbook. Canvas and Three.js pens published in public, one idea at a time, with no obligation to be reusable.

    codepen.io/rexoriousyun

  • 2025 → now

    creative-library

    The corpus. Same techniques, indexed by the problem they solve, each with a harness that fails loudly when a browser moves under it.

02

What is in it

Six families, 37 entries. Each one is a working page, not a gist.

  • Flow fields
  • Dithering
  • Halftone
  • Shader planes
  • Glitch
  • Generative pattern
Flow fields
Motion along a noise field — crowds, currents, hair, anything that should drift instead of tween.
Dithering
Ordered and error-diffusion, on the GPU and off it. Cheap texture where a gradient would be wrong.
Halftone
Dot, line and crosshatch screens with a pitch that survives being resized.
Shader planes
Full-screen fragment work with a uniform contract, so a shader can be dropped into a page in minutes.
Glitch
Channel splits and slice displacement on a step clock — a state, never idle decoration.
Generative pattern
Tiling systems that stay seamless at any viewport, seeded so a reload returns the same page.

Each entry is a working page. The renders above are its own output, written out by the render step so the corpus can be browsed without running any of it.

03

Why a harness

A technique demo rots quietly. A verified one tells you when it broke.

Canvas and WebGL work is exactly the kind of code that stops working without anyone noticing: a driver changes, a context flag flips, a device pixel ratio assumption breaks. Every recipe carries the check that proves it still renders, so the corpus can be reached for on a deadline instead of re-tested by hand.

04

The other shelf

A recipe answers how do I construct this effect. A system answers what does my work look like.

The two are kept deliberately apart. Recipes are meant to be copied into any project and retuned, so nothing under recipes/ depends on a system, and the sync toolchain never reaches into design-system/. One shelf is parts; the other is a point of view.

Rexorious v1.0 is what sits on it: zero radius, notched corners, sheared labels, hazard banding and a four-step motion budget. Nightshift is the default; Daylight exists for print and for anything read longer than two minutes. 59 tokens behind an --rx- prefix, Archivo and Chivo Mono, and a sixteen-section spec that opens in a browser with no server behind it.

It began as a Claude Design export that could not render without React and a template runtime. Porting it to stand on the browser alone meant replacing that layer rather than the design: conditionals became data-if blocks at display:contents, so a hidden branch still sits in its parent’s grid exactly as it did; loops expanded once at startup; and the component’s render step became a hundred lines of script. Sections, markup and copy came across line for line.

You are looking at it. This page is drawn with that token set.

Case 04 · Tree of Knowledge · Digifest 2017

NFC was built for apps. The exhibit needed a website

An interactive installation where visitors tapped physical objects against an iPad and the page changed. Exhibited at Digifest 2017.

01

The constraint

Every NFC framework available assumed a native app. The content was a website, and rewriting it as an app was not the project.

So the iPad ran a thin kiosk-mode shell whose only job was to load the site and forward the tag it had just read into JavaScript. The web page stayed the product; the native layer stayed a driver. On an exhibition floor that also meant it could not fail into a browser chrome or a home screen — kiosk mode was as much about the room as about the tags.

02

What is left of it

The demo is gone — the free hosting tier it lived on was discontinued. Stills and the shape of the build are what is left.

OBJECT ──tap──▶ NFC READER ──▶ KIOSK SHELL ──▶ JS BRIDGE ──▶ ROUTE

SHELL   · loads the site, owns nothing else
BRIDGE  · hands the tag id to the page as an event
PAGE    · the product, unchanged from the browser build

The interaction model and the visual system were both written down before the build — the flow above, and a style guide that still opens: Interface Style Guide (PDF, 12 MB).

Demo link removed

A dead link reads as an unmaintained portfolio, so it does not ship. Stills stand in until the kiosk app is rehosted.
